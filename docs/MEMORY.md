# 记忆模块

推荐入口为 ProjectMemory + turn_reader.ChatMemory。工作细节只在明确进入项目后展开；私人经历保存在指定用户/助手的事件库中，不自动带逐事件项目隔离。

- CompanionMemory：事务账本、来源门控、事件/承诺状态、待确认区、遗忘和更正。
- MemoryScheduler：身份/基础事实、工作和相关往事分区，字符与条数预算。
- ProjectMemory：显式进入/退出、项目概况、工作交接。
- AssociationIndex：从有效事件的 keywords/anchors 临时重建，不保存第二份正文。
- TurnReader：每次请求前读取、生成完整可替换快照。

## 召回

直接检索采用中文二字与英文/数字片段。前者对同义、指代和单字支持有限；英文下划线会分开片段，并非完整编程标识符分析。共享线索和有来源的事件边补充候选，默认最多两轮事件传播，传播种子/候选有上限。

事件 → 线索 → 事件算一轮事件传播，对应图上两条边。自动线索关联按事件年龄衰减，不因读取变强。正文、状态、来源来自本轮账本。已压制和已更正的事件不进入新读取入口；不存在的事件不能继续作关联桥梁。

packet.recall_audit 返回实际注入的事件 ID、路径、相关度、状态和来源。它解释怎样找到内容，不证明内容为真；默认不自动落盘。

## 兼容与写入

旧 CompanionMemory.build_context/retrieve 为兼容仍保留近期补位、旧式注入巩固等行为。新入口 recall_for_scheduler 不补位、不自动增加 recall_count。不要同时运行两套注入。

remember 是可信宿主写入接口；来源型整理仍需宿主提供 llm(prompt)->JSON。confirm 只在用户真正确认后调用，不给模型自行批准。事实的重要度、关系意义、open 状态各有原有规则；本版没有情绪权重联动。

## 删除与数据

forget(keyword) 默认处理长期内容和命中聊天/待整理队列；chat=False 会保留聊天，可能在下一次整理时再产生记忆，不能用于彻底遗忘。suppress 是不再召回，保留记录。删除不能撤回外部模型已读内容，也不清理宿主日志、旧 JSON 与备份。

建议先用账本副本测试。SQLite 保持为权威状态，旧 JSON 是迁移来源而不是实时镜像。详情见根目录 MIGRATION.md。
